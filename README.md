# 🏥 رفاد (Refad) — نظام إدارة شركات توزيع الأدوية

نظام ERP متكامل لإدارة شركات توزيع الأدوية، مبني بتقنيات حديثة:

- **Frontend:** HTML + CSS + Vanilla JavaScript
- **Backend:** Supabase (REST API + Storage + Realtime)
- **PWA:** يعمل offline + قابل للتثبيت
- **اللغة:** عربي (RTL) مع دعم إنجليزي

---

## 🚀 البدء السريع

### 1) إنشاء قاعدة البيانات

افتح [Supabase](https://supabase.com) → SQL Editor → الصق محتوى `supabase.sql` كاملاً → Run. بعده شغّل [returns-setup.sql](./returns-setup.sql) لتفعيل جداول ودالة المرتجعات.

**حساب إدارة الشركات الافتراضي:**
- Username: `superadmin`
- Password: `22446688`

حساب الشركة الافتراضي: `admin` / `22446688`. عند إنشاء قاعدة بيانات موجودة مسبقاً، شغّل `superadmin-setup.sql` من SQL Editor لإضافة حساب إدارة الشركات دون إعادة إنشاء الجداول. بيانات تسجيل الدخول تُقرأ من جدول `users`؛ لتغيير كلمة المرور الافتراضية حدّث حقل `password` للحساب `superadmin` من قاعدة البيانات.

### 2) إنشاء Storage Buckets

المخطط الأساسي ينشئ `logos` و`chat-files` كحاويتين Public. النسخ الاحتياطي ينشئ حاوية `refad-backups` الخاصة تلقائياً بواسطة `backup-schedule-setup.sql`؛ لا تجعلها Public.

لترقية قاعدة بيانات موجودة، لا تعِد تشغيل `supabase.sql` لأنه يبدأ بحذف المخطط. شغّل ملفات الترحيل المطلوبة مرة واحدة:

- `superadmin-setup.sql` لتجهيز مدير الشركات والصلاحيات.
- `notifications-setup.sql` لإتاحة إشعارات فورية داخل التطبيق وتفعيل جدول الإشعارات في Supabase Realtime.
- `companies-currency-setup.sql` لإضافة عملة الشركة إذا لم تكن موجودة.
- `sales-supplier-setup.sql` لبيع الأصناف للموردين وربط فواتير البيع.
- `purchase-request-response-setup.sql` لخصومات طلبات الشراء وردود الموردين.
- `returns-setup.sql` لإنشاء سجل المرتجعات ودالة حفظ ذرّية تحدّث التشغيلات والأرصدة، وإضافة صلاحيات مرتجع المبيعات والمشتريات للأدوار التي تملك صلاحية المجال المناسبة.
- `representative-settlements-setup.sql` لتسجيل التحصيلات من المندوبين وتحديث المبلغ المحصل وحالة فاتورة البيع ذرياً.

### 3) النسخ الاحتياطي

من إعدادات الشركة افتح **النسخ الاحتياطي** لتنزيل نسخة يدوية مشفّرة بكلمة مرور تختارها. كلمات مرور مستخدمي النظام لا تدخل في النسخة. احتفظ بكلمة مرور التشفير خارج النظام؛ لا توجد آلية لاستعادتها. النسخة أرشيف JSON مشفّر ولا تتوفر حالياً استعادة مباشرة من داخل النظام.

لتفعيل النسخ السحابي اليومي:

1. انشر الدالة بالأمر `supabase functions deploy refad-backup --project-ref YOUR_PROJECT_REF`.
2. عيّن قيمة عشوائية قوية باسم `BACKUP_CRON_SECRET` في أسرار Edge Functions، ثم أضف القيمة نفسها في Supabase Vault بالاسم `refad_backup_cron_secret`.
3. استبدل `YOUR_PROJECT_REF` في `backup-schedule-setup.sql` بمعرّف مشروع Supabase، ثم شغّل الملف في SQL Editor.
4. تحقق من أول تشغيل عبر Edge Function Logs وحاوية `refad-backups` الخاصة. يعمل الجدول يومياً الساعة 02:00 UTC ويحتفظ بآخر 30 يوماً.

ينشئ ملف الجدولة حاوية `refad-backups` الخاصة تلقائياً؛ لا تغيّرها إلى Public.

النسخ السحابي يحتوي بيانات قاعدة البيانات للشركات، ولا يتضمن كلمات مرور المستخدمين أو الملفات الثنائية المخزنة خارج قاعدة البيانات. النسخة اليدوية والسحابية لا تستبدلان نسخ PostgreSQL الأصلية لدى Supabase.

### 4) تشغيل الباركود في البيع والشراء

يدعم البحث في نقطة البيع والاستلام وطلبات الشراء قارئ الباركود USB/Bluetooth الذي يعمل كلوحة مفاتيح، مع إدخال تلقائي وإنهاء القراءة بزر Enter. تتوفر قراءة بالكاميرا في نقطة البيع والاستلام وطلبات الشراء؛ يلزم HTTPS أو `localhost` والسماح باستخدام الكاميرا. مسح الطلبات يضيف وحدة للكمية المطلوبة في كل قراءة، بينما مسح فاتورة الاستلام أو البيع يزيد كمية الصنف وفق قواعد الشاشة.

تصل الإشعارات داخل النظام فوراً عبر Supabase Realtime، مع فحص احتياطي دوري كل 20 ثانية إذا تعطل الاتصال الفوري. تُرسل تنبيهات المخزون المنخفض والصلاحيات من لوحة التحكم أو صفحة المخزون مرة يومياً لكل صنف/تشغيلة، كما يصدر البيع تنبيهاً عند نزول الصنف إلى حد إعادة الطلب. يتطلب صندوق الإشعارات صلاحية `notifications.view` وصلاحية المجال المناسب لنوع التنبيه؛ لتفعيل الصلاحيات للمستخدمين الحاليين أعد تشغيل `notifications-setup.sql` مرة واحدة على قاعدة قائمة ثم سجّل الخروج والدخول لتحديث صلاحيات الجلسة. إشعارات نظام التشغيل اختيارية: اسمح بها من زر الجرس في صفحة الإشعارات، وتحتاج HTTPS (أو localhost).

### 5) إدارة المشتريات والمبيعات

يطبع إيصال نقطة البيع والفاتورة المعاد طباعتها بيانات الشركة المحفوظة في جدول `companies`، بما في ذلك الاسم والشعار والعنوان والهاتف والبريد والرقم الضريبي. حدّث بيانات الشركة من إعداداتها قبل الطباعة.

يعرض تقرير المخزون كميات الشراء المقترحة وفق مبيعات آخر 90 يوماً، وحد إعادة الطلب، ومخزون صالح للبيع، مع تنبيهات التشغيلات المنتهية أو التي تنتهي خلال 30 يوماً. يمكن تحويل التوصيات إلى مسودة طلب شراء؛ تظل الكميات قابلة للتعديل ولا يُنشأ طلب أو يتغير المخزون إلا بعد مراجعة المستخدم وحفظه.

يعرض نموذج طلب الشراء أيضاً الرصيد المتاح، وكمية تغطية مقترحة، وأقل سعر شراء صافٍ مسجل لكل مورد خلال آخر 180 يوماً. خصم الشراء المقترح هو أعلى خصم سابق للصنف، ويُضاف إلى الطلب فقط عند اختياره يدوياً. تعرض نقطة البيع خصماً استرشادياً من سجل الصنف، محدوداً بما لا يخفض الربح إلى أقل من الصفر؛ لا يُطبّق تلقائياً. يمكن فتح فاتورة البيع أو الشراء بالنقر على أي مكان في صفها، مع بقاء أزرار العرض والطباعة والحذف مستقلة.

في فاتورة الاستلام، تحميل طلب الشراء ينقل الخصم المطلوب لكل صنف كما هو إلى الاستلام، وسعر المورد المردود إن وُجد. يمكن مسح باركود الصنف عدة مرات لإضافة كميته، وتظل كاميرا المسح مفتوحة للفحص المتتابع؛ وبعد تحديد الصنف يمكن مسح باركود التشغيلة لربطه به، وإدخال رقم التشغيلة والصلاحية في حقلين متجاورين. يتيح زر «إضافة تشغيلة أخرى» تسجيل دفعات متعددة للصنف نفسه. لتخزين باركود التشغيلة في قاعدة قائمة، شغّل [batch-barcode-migration.sql](./batch-barcode-migration.sql) مرة واحدة قبل استخدام النسخة الجديدة. طباعة الاستلام وطباعة البيع تعرضان اسم الشركة وشعارها وبياناتها المخزنة في قاعدة البيانات، كما تعرض السلة في نقطة البيع مساحة أكبر لقائمة الأصناف.

### 6) لوحة الحسابات

تظهر لوحة [الحسابات](./accounts.html) لصاحب الشركة فقط، وتلخص المبيعات والتحصيلات والأرباح المسجلة والمشتريات المستلمة والمصاريف وأرصدة العملاء والموردين، مع تحديد الفترة ومخطط حركة آخر 14 يوماً وتصدير CSV. الأرصدة المعروضة مصدرها أرصدة حسابات الأطراف الحالية، والنتيجة بعد المصاريف تقديرية وليست بديلاً عن دفتر قيود. لا تتضمن النسخة الحالية قيوداً يومية أو إدارة صناديق وبنوك أو سندات قبض وصرف؛ يلزم تصميم جداول وتدفقات مالية مستقلة قبل استخدامها كمحاسبة رسمية.

لتمكين تسوية حساب المندوب، شغّل [representative-settlements-setup.sql](./representative-settlements-setup.sql) مرة واحدة في Supabase SQL Editor. من قسم «تسوية حسابات المندوبين» في صفحة الحسابات تظهر الفواتير المفتوحة المرتبطة بمدخل الفاتورة (الكاشير/المندوب)، ويمكن تسجيل التحصيل كاملاً أو جزئياً مع ملاحظة. يسجل النظام من استلم التحصيل وتاريخه ومبلغه؛ وتتحول الفاتورة إلى «مدفوعة» تلقائياً عند تغطية كامل المتبقي، أو تبقى «جزئية» عند التحصيل الجزئي. تظهر هذه السجلات في النسخة الاحتياطية أيضاً.

تظهر وصلة الحسابات في القائمة الجانبية لصاحب الشركة في صفحات النظام، كما تفتح صفوف الفواتير والاستلامات وطلبات البيع والشراء تفاصيل السجل؛ صفوف الأصناف والموردين والعملاء تفتح صفحة تفاصيل الطرف أو الصنف.

### 7) المرتجعات وحركات الصنف

لتفعيل المرتجعات على قاعدة موجودة أو جديدة، شغّل أحدث نسخة من [returns-setup.sql](./returns-setup.sql) في Supabase SQL Editor بعد المخطط الأساسي؛ يمكن إعادة تشغيله لتحديث الدالة، وهو يعيد تحميل مخطط PostgREST بعد التنفيذ. تستخدم الصفحة صلاحية عرض المبيعات لمرتجع البيع وصلاحية استلام المشتريات لمرتجع المورد. من صفحة [المرتجعات](./returns.html) يمكن اختيار فاتورة بيع أو استلام أصلية، تحديد سبب وكميات الأصناف ثم حفظ المرتجع. يتحقق الحفظ الذري من الكميات المرتجعة السابقة، يزيد مخزون التشغيلة عند إرجاع العميل ويخفضه عند إرجاع الصنف للمورد، ويعكس قيمة المرتجع في رصيد الطرف. لا يتيح النظام إرجاع بند فاتورة بيع غير مربوط بتشغيلة، ويعرض ذلك على البند لتفادي زيادة مخزون غير محدد. رد النقدية الفعلي يحتاج سند صرف/قبض مستقل، لذلك تعرض الشاشة هذا القيد بوضوح.

يعرض سجل حركات الصنف الطرف المرتبط، ورقم الفاتورة/الاستلام؛ الصف يفتح المستند الأصلي مباشرة. يشمل ذلك الحركات المنشأة من المرتجعات بعد تشغيل الترحيل.
