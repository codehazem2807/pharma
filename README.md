# 🏥 رفاد (Refad) — نظام إدارة شركات توزيع الأدوية

نظام ERP متكامل لإدارة شركات توزيع الأدوية، مبني بتقنيات حديثة:

- **Frontend:** HTML + CSS + Vanilla JavaScript
- **Backend:** Supabase (REST API + Storage + Realtime)
- **PWA:** يعمل offline + قابل للتثبيت
- **اللغة:** عربي (RTL) مع دعم إنجليزي

---

## 🚀 البدء السريع

### 1) إنشاء قاعدة البيانات

افتح [Supabase](https://supabase.com) → SQL Editor → الصق محتوى `supabase.sql` كاملاً → Run.

**حساب إدارة الشركات الافتراضي:**
- Username: `superadmin`
- Password: `22446688`

حساب الشركة الافتراضي: `admin` / `22446688`. عند إنشاء قاعدة بيانات موجودة مسبقاً، شغّل `superadmin-setup.sql` من SQL Editor لإضافة حساب إدارة الشركات دون إعادة إنشاء الجداول. بيانات تسجيل الدخول تُقرأ من جدول `users`؛ لتغيير كلمة المرور الافتراضية حدّث حقل `password` للحساب `superadmin` من قاعدة البيانات.

### 2) إنشاء Storage Buckets

المخطط الأساسي ينشئ `logos` و`chat-files` كحاويتين Public. النسخ الاحتياطي ينشئ حاوية `refad-backups` الخاصة تلقائياً بواسطة `backup-schedule-setup.sql`؛ لا تجعلها Public.

لترقية قاعدة بيانات موجودة، لا تعِد تشغيل `supabase.sql` لأنه يبدأ بحذف المخطط. شغّل ملفات الترحيل المطلوبة مرة واحدة:

- `superadmin-setup.sql` لتجهيز مدير الشركات والصلاحيات.
- `notifications-setup.sql` لإتاحة إشعارات فورية داخل التطبيق وتفعيل جدول الإشعارات في Supabase Realtime.
- `companies-currency-setup.sql` لإضافة عملة الشركة إذا لم تكن موجودة.
- `sales-supplier-setup.sql` لبيع الأصناف للموردين وربط فواتير البيع.
- `purchase-request-response-setup.sql` لخصومات طلبات الشراء وردود الموردين.

### 3) النسخ الاحتياطي

من إعدادات الشركة افتح **النسخ الاحتياطي** لتنزيل نسخة يدوية مشفّرة بكلمة مرور تختارها. كلمات مرور مستخدمي النظام لا تدخل في النسخة. احتفظ بكلمة مرور التشفير خارج النظام؛ لا توجد آلية لاستعادتها. النسخة أرشيف JSON مشفّر ولا تتوفر حالياً استعادة مباشرة من داخل النظام.

لتفعيل النسخ السحابي اليومي:

1. انشر الدالة بالأمر `supabase functions deploy refad-backup --project-ref YOUR_PROJECT_REF`.
2. عيّن قيمة عشوائية قوية باسم `BACKUP_CRON_SECRET` في أسرار Edge Functions، ثم أضف القيمة نفسها في Supabase Vault بالاسم `refad_backup_cron_secret`.
3. استبدل `YOUR_PROJECT_REF` في `backup-schedule-setup.sql` بمعرّف مشروع Supabase، ثم شغّل الملف في SQL Editor.
4. تحقق من أول تشغيل عبر Edge Function Logs وحاوية `refad-backups` الخاصة. يعمل الجدول يومياً الساعة 02:00 UTC ويحتفظ بآخر 30 يوماً.

ينشئ ملف الجدولة حاوية `refad-backups` الخاصة تلقائياً؛ لا تغيّرها إلى Public.

النسخ السحابي يحتوي بيانات قاعدة البيانات للشركات، ولا يتضمن كلمات مرور المستخدمين أو الملفات الثنائية المخزنة خارج قاعدة البيانات. النسخة اليدوية والسحابية لا تستبدلان نسخ PostgreSQL الأصلية لدى Supabase.

### 4) تشغيل الباركود في البيع والشراء

يدعم البحث في نقطة البيع والاستلام وطلبات الشراء قارئ الباركود USB/Bluetooth الذي يعمل كلوحة مفاتيح، مع إدخال تلقائي وإنهاء القراءة بزر Enter. تتوفر قراءة بالكاميرا في نقطة البيع والاستلام وطلبات الشراء؛ يلزم HTTPS أو `localhost` والسماح باستخدام الكاميرا. مسح الطلبات يضيف وحدة للكمية المطلوبة في كل قراءة، بينما مسح فاتورة الاستلام أو البيع يزيد كمية الصنف وفق قواعد الشاشة.

تظهر الإشعارات المباشرة كتنبيه داخل النظام أثناء استخدامه، ويمكن أن تظهر كإشعار متصفح إذا سبق السماح بها. تأكد من صلاحية `notifications.view` وصلاحية القسم المطلوب للمستخدم، وشغّل `notifications-setup.sql` مرة واحدة على قاعدة قائمة.

### 5) إدارة المشتريات والمبيعات

يطبع إيصال نقطة البيع والفاتورة المعاد طباعتها بيانات الشركة المحفوظة في جدول `companies`، بما في ذلك الاسم والشعار والعنوان والهاتف والبريد والرقم الضريبي. حدّث بيانات الشركة من إعداداتها قبل الطباعة.

يعرض تقرير المخزون كميات الشراء المقترحة وفق مبيعات آخر 90 يوماً، وحد إعادة الطلب، ومخزون صالح للبيع، مع تنبيهات التشغيلات المنتهية أو التي تنتهي خلال 30 يوماً. يمكن تحويل التوصيات إلى مسودة طلب شراء؛ تظل الكميات قابلة للتعديل ولا يُنشأ طلب أو يتغير المخزون إلا بعد مراجعة المستخدم وحفظه.
